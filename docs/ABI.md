# OpenCPU LLVM ABI v1

本文件约定首版原生 LLVM 后端输出的独立程序。指令编码和硬件行为以 [ISA v2](ISA.md) 为准；
极简 `.oc` 编译器继续保留自己的实现。两条编译链共用镜像格式，但首版不承诺函数级混合调用、
Clang/C 数据模型、ELF 或多文件链接。

## 入口与寄存器

主机工具在 LLVM 输出前添加 [启动汇编](../software/runtime/startup.asm)：

```asm
_start:
    li sp, 1024
    li fp, 0
    call main
    halt
```

`_start` 是保留名称；模块必须定义无参数、返回 `i16` 或 `void` 的 `main`。
ROM 入口和 `BuildResult.entry_pc` 都是字地址零。返回后执行 HALT，`i16` 返回值留在 `a1`。
软件模拟器和 IDE 也从此处启动，不能跳过初始化直接运行 `main`。

| 寄存器 | 用途 |
|---|---|
| `r0/zero` | 硬件常数零，不分配 |
| `r1–r4/a1–a4` | 最多四个 `i16` 参数，按顺序传递；普通临时寄存器，调用者保存 |
| `r1/a1` | `i16` 返回值；`void` 函数不约定返回值 |
| `r5/fp` | 固定保留的帧指针，保存物理字地址 |
| `r6/ra` | 链接寄存器，保存返回指令的字地址 |
| `r7/sp` | 向低地址增长的栈指针，保存物理字地址 |

每个函数保存、恢复 FP 和 RA。普通寄存器跨调用的活跃值由 LLVM 保存或重新计算；
CALL 描述包含调用者保存寄存器的破坏信息。函数返回后 SP/FP 恢复调用前的值。
首版不提供外部函数、可变参数、结构体参数/返回值、尾调用要求或中断处理函数 ABI。

## 地址、栈帧与内存

LLVM 的类型布局、栈对象尺寸和帧偏移按标准 **8 位字节** 计算；硬件的 PC、SP、FP 及 LW/SW
地址按 **16 位字** 计算。`i16` 占两个 LLVM 字节、一个硬件字；栈对齐为两个字节。
FrameLowering 和 FrameIndex 消除必须先验证尺寸/偏移为偶数，再除以二发射硬件字偏移。

首版只允许静态 `i16` 标量或定长 `i16` 数组的 alloca，以及常量 GEP 派生的直接帧内访问。
显式对齐必须为 2，省略对齐使用目标的自然对齐。GEP 的常量索引可以采用 LLVM 常见的
`i32` 索引常量，但最终访问必须为对齐的 `i16`，位于相应分配对象范围内。
指针不能作为函数参数/返回值、存入内存、转换为整数或逃逸到一般表达式。

大帧偏移超出 LW/SW 的 `-16..15` 字范围时，后端分段调整保留的 FP，执行访存后反向恢复。
该展开不占用第四个参数寄存器，也不在寄存器分配后创建临时虚拟寄存器。

默认 RAM 为 1024 字；程序需要控制总体栈使用和递归深度。首版没有通用堆、全局数据、
字节访存 ABI 或 MMIO/CSR 内建函数。LLVM 指针在此处仅用于限定的栈对象寻址，不能据此推断
一般 C 指针、字符串或结构体布局已受支持。

UART 高字节先发是镜像传输规则，与 LLVM 的字节布局约定分别定义；参见 [硬件说明](../hardware/README.md)。

## 支持的 LLVM IR

| 类别 | 首版支持 |
|---|---|
| 数据值 | `i16`；比较/条件使用 `i1` |
| 整数操作 | `add/sub/mul/and/or/xor/shl/lshr` |
| 比较 | `icmp` 的相等、不等、全部有符号与无符号大小比较 |
| 布尔转换 | `trunc i16 → i1`，`zext/sext i1 → i16` |
| 控制流 | `ret`、无条件/条件 `br`、`phi`、`select` |
| 调用 | 模块内直接调用、0–4 个 `i16` 参数、`i16/void` 返回、递归 |
| 内存 | 上述固定 alloca、常量 GEP、对齐的帧内 `i16 load/store` |
| 标记 | 调试与 lifetime 标记可被忽略 |

不支持的项由原生 LLVM 后端诊断：其他数据位宽、浮点/vector/聚合参数、除法/余数、`ashr`、
动态 alloca/GEP、一般指针、全局数据、外部函数、函数指针、varargs、内联汇编、原子操作、
异常和其他 intrinsic。不得默默生成尚未提供的 libcall。

程序仍须遵守 LLVM IR 的语义，例如有效移位量为 `0..15`；`poison`、`undef` 以及
`nsw/nuw` 约束不能按极简语言或硬件的溢出、移位规则自行解释。

## 构建产物与验证

真实 `llc -march=opencpu -O0 -filetype=asm` 输出 OpenCPU 汇编方言，Python 汇编器负责
常量/远分支展开、标签布局和最终 16 位字编码。默认 ROM 上限为 1024 字，超容量镜像报错。
`source_map` 对应包含启动代码在内的最终汇编行，不表示 `.ll` 源码调试映射；
LLVM 的 `variable_offsets` 为空。

验收同时检查 `a1` 的独立预期值、HALT、SP/FP 恢复以及软件模型与真实 UART 上传的 RTL 状态。
两套编译器可生成不同指令序列，验证以各自语言语义和本 ABI 为准。
