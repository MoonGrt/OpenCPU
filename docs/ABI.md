# OpenCPU LLVM ABI v2

本约定适用于原生 LLVM `.ll` 和 Clang C17 编译链，指令编码与硬件行为以 [ISA v2](ISA.md) 为准。
极简 `.oc` 编译器保留自身 ABI 和原有机器码；两条编译链共用镜像格式，暂不提供函数级混合调用。
本轮生成完整的裸机镜像，不提供 ELF、操作系统、完整 libc 或 C++。

## C 类型模型

目标 triple 为 `opencpu-unknown-none`，采用小端字节布局。

| C 类型 | 位宽 | 对齐（字节） |
|---|---|---|
| `_Bool`、`char`、`signed char`、`unsigned char` | 8 | 1 |
| `short`、`int` 及对应无符号类型 | 16 | 2 |
| `long`、`unsigned long` | 32 | 2 |
| `long long`、`unsigned long long` | 64 | 2 |
| 数据指针 | 16 | 2 |

`char` 默认有符号；`CHAR_BIT=8`，`size_t` 为 `unsigned int`，`ptrdiff_t` 为 `int`。
`sizeof`、数组步长和 LLVM 类型布局均使用标准 8 位字节单位。
浮点类型的布局信息用于 Clang 一致性检查，不表示本轮支持浮点计算。

支持整数表达式、类型转换、条件/循环、`switch`、直接调用和递归；支持固定大小数组的动态下标、
RAM 数据指针、全局与静态变量、字符串及多 C 翻译单元。
结构体、联合体、位域、函数指针、浮点、VLA、可变参数、原子操作、线程和内联汇编不在支持范围。
不提供高于两字节的显式对象对齐或中断处理函数 ABI。

整数遵循 C/LLVM 语义：无符号运算按对应位宽回绕；有符号溢出、除零、越界访问和非法移位量不能
作为有效程序使用。有符号右移采用算术右移，合法移位量为零至值位宽减一。

## 入口与调用约定

主机在 LLVM 汇编前添加 [启动代码](../software/runtime/startup.asm)，从 ROM 字地址零执行：

```asm
_start:
    li sp, 1024
    li fp, 0
    call __opencpu_init_data
    call main
    halt
```

C 程序必须提供 `int main(void)`，并显式返回结果；freestanding 模式不假定省略 `return` 就返回零。
原有 `.ll` 输入仍可定义无参、返回 `i16` 或 `void` 的 `main`。初始化例程由后端生成，先初始化
静态数据，再进入 `main`；返回后 HALT，`i16` 返回值留在 `a1`。`_start` 和 `__opencpu_` 前缀为保留名称。
软件模拟器与 IDE 使用 `BuildResult.entry_pc=0`，从启动代码开始执行。

| 寄存器 | 用途 |
|---|---|
| `r0/zero` | 硬件常数零，不参与分配 |
| `r1–r4/a1–a4` | 参数槽、返回值及普通临时值；调用者保存 |
| `r5/fp` | 固定帧指针，保存硬件字地址 |
| `r6/ra` | 返回指令的硬件字地址 |
| `r7/sp` | 向低地址增长的栈指针，保存硬件字地址 |

参数按声明顺序拆成低字在前的连续 16 位槽，前四槽使用 `a1–a4`，其余由调用者放入栈参数区；
同一个 32/64 位参数可以跨寄存器与栈，不额外插入槽间空洞。窄参数按符号或零扩展占用一槽，
`_Bool` 零扩展，数据指针占一槽。调用结束由调用者回收栈参数区。
16 位及以下结果使用 `a1`，32 位结果使用 `a1/a2`，64 位结果使用 `a1–a4`；宽结果均低字在前。

每个函数保存并恢复 FP/RA。跨调用活跃的参数寄存器由 LLVM 保存或重新计算。
函数返回后 SP/FP 恢复到调用前的值；大栈帧和参数区调整不在寄存器分配后创建虚拟临时寄存器。

## RAM、指针与外设

默认 RAM 为 1024 个 16 位字，C 将其视作 2048 个字节。字节地址 0–1 不分配对象，普通指针的
零值用于空指针；静态数据从字节地址 2 开始，栈从字节地址 2048 向下增长。
数据与栈共用 RAM。静态数据超过容量时报错，栈帧和栈参数区分配检查静态区边界，耗尽时触发故障。
递归深度受剩余 RAM 限制。

SP/FP 与硬件 LW/SW 使用字地址，LLVM/C 指针、GEP 和对象尺寸使用字节地址。
后端负责转换：自然对齐的 16 位访问将指针除二；8 位访问选择所在字的高低字节，写入通过读改写
保留相邻字节。宽整数按低字在前拆成多个字。栈对象允许奇字节偏移，整帧大小向两字节对齐。

ROM 不提供普通数据读取接口，因此字符串、`const` 对象和其他静态初值也放入 RAM。
后端分配静态地址，并生成清零与初值写入代码；这些代码同样占用 1024 字 ROM。
全局对象地址是 RAM 字节数值，不能使用表示代码字地址的汇编 `la`。

16 位字节指针不能表示全部硬件 MMIO 字地址。使用 SDK 的 `<opencpu.h>`：

```c
#include <opencpu.h>

unsigned value = opencpu_mmio_read16(0xff00u);
opencpu_mmio_write16(0xff01u, value);
```

上述接口参数为硬件**字地址**，通过目标 builtin 发出有副作用的 LW/SW，不执行普通指针的除二转换。
具体寄存器地址和访问规则见 [ISA](ISA.md)及[硬件说明](../hardware/README.md)。
不要把 MMIO 字地址直接强制转换成普通 C 指针。字节读改写不是原子操作，普通指针只承诺 RAM 访问。

## 编译、运行库与产物

每个 C 文件由同版 Clang 编译为 bitcode，`llvm-link` 合并用户翻译单元，`llc -march=opencpu -O0`
执行目标准备和指令选择。准备阶段降低控制流及需要运行库的操作，然后按需导入
`lib/opencpu/runtime.bc`，清除无用定义，再验证 ABI。
整数 helper 使用 16 位分片实现，此外提供 `memcpy/memmove/memset/memcmp`；没有隐式宿主库依赖。
缺失符号、工具或运行库均为构建错误，禁止默默生成未提供的 libcall。

汇编器负责常量、远分支、调用展开和最终 16 位编码；默认 ROM 上限仍为 1024 字，超容量报错。
UART 高字节先发是镜像传输规则，与 RAM 小端字节布局分别定义。
`source_map` 对应包含启动代码的最终汇编行，不是 C/IR 源码调试映射；LLVM 的 `variable_offsets` 为空。
构建结果记录语言、`llvm-v2` ABI、依赖文件指纹和静态数据结束字节地址（包含保留的两个字节）。

验收检查独立预期结果、HALT、数据初始化、SP/FP 恢复，并逐退休对照软件模型与真实 UART 上传后的 RTL。
两套编译器可生成不同指令序列；极简版按其语言与 ABI 验证，LLVM 按本文件验证。
